# 合并艺术 Skill 仓库

## 目标与现状

用户要求把韦斯、达利、莫奈及艺术风格元 Skill 合并到名为 `artist-skill` 的仓库，并整理全部输出。四个现有源码目录均没有 Git 历史；本次完成本地整合，初始化本地 Git，不涉及远端发布。

现有输出主要集中在韦斯目录，其中五组实际属于达利。部分本次生成图、提示、评审与交互式字体/色板示意仍在任务工作区。两个 Skill 发现目录目前混用实体副本和符号链接，容易产生不同步。

## 方案与边界

- 将四个源码目录移动到 `/Users/yijunwang/code/artist-skill/skills/<skill-name>`，保留 Skill 名称与全部运行文件内容。
- 每个艺术 Skill 的 `outputs/<topic>` 保存对应题材的原图、各版本、实际提示及已有评审；补齐工作区和本次生成缓存中尚未入库的图像。相同图片仅保留一份，已有版本名称不改写为新的质量结论。
- 莫奈的平铺输出移入 `outputs/pond-after-rain`。五组达利输出从韦斯目录移到达利目录。
- 收纳本次两份研究记录及字体、色板 HTML。保存原始提示内容，更新新索引与迁移后研究记录中的相对链接；历史提示中的旧参考路径作为当时记录保留。
- `dist/` 保存四个当前独立包、一个合集包及旧合集归档；当前包只含 Skill 运行文件，不包含作品、用户参考图、研究或评审。
- 将 `.codex/skills` 和 `.agents/skills` 中这四个入口统一链接到新源码。旧安装副本与两份完全相同的“副本”图片暂存任务工作区备份。
- 根 README 说明结构、四个入口、作品目录、包边界；不重新研究风格，不新增出图，不修改创作规则，不删除全局图像缓存。工作区原产物保留作历史任务记录。

## 输入输出与依赖

输入是四个现有 `/code` 目录、本次任务 `outputs` 与指定的生成图片，以及两处现有 Skill 入口。输出是一个本地仓库、按 Skill/题材整理的作品与文档、可继续使用的发现入口及更新的 ZIP。依赖本机 Python、Git、现有 Skill 验证器；迁移目标须不存在，源目录须存在且入口内容与源码一致。
