# 北京深秋：布局与比例的 Grok 实测

2026-09-11。根据本次用户两图反馈修改韦斯 Skill，在本地据新版规则编排具体提示，由 Grok 执行 1 次 `image_gen` 和 2 次 `image_edit`。新生成没有参考图；编辑仅使用本次 Grok 上一版输出。没有将用户朋友的拍屏图或用户原图传给 Grok，也不要求保持原例人物身份。

## 本次结果

| 项目 | 判断 | 可见依据 |
| --- | --- | --- |
| 人体自身比例 | 较原例改善 | 大衣到膝部，下肢和脚部清楚，头、躯干、四肢之间没有原例那样明显的压短观感；没有依靠一律拉长腿来修正 |

| 整体布局 | 部分通过，未达到本次明确要求 | 大形、院门结构、人物/车轮廓和上方文字区域清楚；自行车从裁断变为完整。但三版中人物都没有移动到院门中央门缝，主要轴线要求未执行，不能仅凭有对称建筑就判定整体通过 |

| 独立运行与泛化 | 未验证 | 未验证 Grok 自主读取整份新版 Skill 的流程，也未验证其他题材、群像、其他图像模型或照片保真 |

最终判断：规则修订和真实 Grok 出图完成，视觉结果只部分达到要求。两次有目的的布局编辑仍未落实人物移位，停止继续叠加同一问题的提示。本例不能作为整套 Skill 已稳定通过的正面基准，也不以工具成功代替用户审美判断。

## 规则与执行的区别

新版 Skill 已把全图布局、对象自身结构、相互尺度、透视与支撑同时写入构想、生成提示与结果检查，保留现有色彩、字体及用户覆盖要求。此次没有根据编辑工具忽略位移，继续往公共 Skill 叠加像素坐标、北京场景或固定头身比。

直接让 Grok 读取本地完整 Skill 的方案被自动审批拒绝，理由为私有文件对外披露授权不足。本次采用范围更小的执行方式：本地应用 Skill，只将具体海报提示交给 Grok。此限制没有阻止实际 Grok 出图，但“模型自己读取 Skill 并编排提示”的流程未运行。
